# Decisions

Choices the specification leaves open, logged as required by `DMI_BRD_for_Claude_Code.md` section 0, rule 3. Newest milestone last.

## M0 Orientation

| Date | Decision | Reason |
|---|---|---|
| 2026-09-30 | **Repository detection (BRD 3.3): not inside BEAM.** The repository held only the two specification files, with no application code, package manifest or BEAM configuration. Building a standalone app on the reference stack (BRD 4.2), mounted at `APP_BASE_PATH` and ready to swap its auth for BEAM's later. | Step 1 of the detection procedure found no BEAM application. |
| 2026-09-30 | **Versions installed:** Node 26.5 locally (Node 24 LTS in Docker and CI), Next.js 16.3.7 (App Router, Turbopack), React 19.3.0, TypeScript 5.9.3 (strict, plus `noUncheckedIndexedAccess`), ESLint 9.39 with `eslint-config-next` 16.3.7, Vitest 5.0.2, Playwright 1.63.0, `@axe-core/playwright` 4.13.0, `lucide-react` 1.49.0. | BRD 4.2 asks for exact versions. |
| 2026-09-30 | **TypeScript 5.9, not 7.0.** TypeScript 7 (the native port) is the current `latest` tag, but Next.js type checking and `typescript-eslint` depend on the JavaScript compiler API. Revisit once both support 7. | Tooling compatibility. |
| 2026-09-30 | **Single app at the repository root**, not a monorepo. The worker (M3) will be a second entry point in the same package sharing `src/`, built into its own Docker target. | Smallest structure that meets BRD 4.3; easy to move into `apps/intelligence` if this is later merged into BEAM. |
| 2026-09-30 | **Fonts self-hosted through `next/font/google`**, which downloads the files at build time and serves them from the app origin. The `--font-display`, `--font-sans` and `--font-mono` tokens are re-pointed at the `next/font` variables in `globals.css`, with the design file's fallback stacks unchanged. `tokens.css` is otherwise a verbatim copy of design file section 2.2. | Design file 2.1 prefers self-hosting for the Content Security Policy (BRD 18.3). Same families and weights. |
| 2026-09-30 | **CSS custom properties plus CSS Modules**, with shared primitives (`.btn`, `.card`, `.pill`, type styles) as global classes in `globals.css`, copied from design file section 8. Breakpoints are written as literal pixel values (560, 760, 960, 1200) because custom properties cannot be used in media queries. | BRD 4.2 styling choice; design file 2.4. |
| 2026-09-30 | **Every page renders per request** (`dynamic = "force-dynamic"` in the root layout). | The session and `DATA_MODE` (which drives the Mock data badge) must be read at request time, never baked in at build time. |
| 2026-09-30 | **Navigation icons are passed as names** (`"people"`) and resolved to Lucide components inside the client `SidebarNav`. | React server components cannot pass component functions to client components. |
| 2026-09-30 | **Top bar below 560 px:** the global search field moves from the top bar into the navigation drawer, and the top bar gutter drops to 16 px. At 320 px the burger, brand, Mock data badge and user menu would not fit alongside a search field. The content area keeps the 24 px gutter. | Design file 2.4 requires zero horizontal scroll at 320 px; it does not specify the top bar at that width. New pattern built from existing tokens (design file precedence rule 3). |
| 2026-09-30 | **Placeholder session** (`src/lib/session.ts`): a fictional partner, "Jordan Example", in "Demo Search Partners", so the shell can render before auth exists. Replaced in M1. | M0 scope is the app shell; auth is M1. |
| 2026-09-30 | **Mock data badge logic:** shown when `DATA_MODE=mock`, or when no `ANTHROPIC_API_KEY` is set (the AI adapter then falls back to mock, BRD 17.4). Extended per adapter in M3. | Design file 4.2 and checklist item "Mock data badge visible when any adapter is in mock mode". |
| 2026-09-30 | **Standalone output:** `next build` emits `.next/standalone`; `npm start` copies static assets into it and runs `server.js`. The Docker image runs the same server as a non-root user. | Small image, no dev dependencies in production. |
| 2026-09-30 | **Local toolchain gap:** Docker and PostgreSQL are not installed on the development laptop. `Dockerfile` and `docker-compose.yml` are written but not yet run locally; CI runs lint, type-check, unit tests, the dependency scan and the Playwright suite. M1 needs a PostgreSQL 16 instance for migrations and the tenancy tests. | Recorded so the M1 setup step is not forgotten. |
